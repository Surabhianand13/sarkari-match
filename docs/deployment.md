# Deployment (Render + Render Postgres, Cloudflare in front)

1. Create the stack from `render.yaml` (web service `sarkarimatch-web` + Postgres `sarkarimatch-db`). Use paid plans: free Postgres expires after 30 days and free web services sleep, which hurts crawling.
2. Set `NEXT_PUBLIC_SITE_URL` to the real domain (it drives canonical URLs, the sitemap and `llms.txt`). `AUTH_SECRET` is generated by the blueprint; `DATABASE_URL` is injected from the database.
3. Migrations run automatically before each deploy (`pnpm db:migrate`). Load the taxonomies once with `pnpm db:seed` from a shell that has the production `DATABASE_URL`. Do not run `db/seed/0003_sample_notifications.sql` in production.
4. Create the first admin: `pnpm db:create-admin` (prompts for email and password; nothing is stored in the repo).
5. Cloudflare: add the domain, proxy the Render hostname, cache static assets, and leave HTML caching to the Next.js ISR headers. Enable bot protection but allow Googlebot, Bingbot and the AI crawlers listed in `app/robots.ts`.
6. Configure Resend (`RESEND_API_KEY`, `EMAIL_FROM`) so email sign-in codes are delivered. Without it codes are only logged in development.
7. Configure Razorpay keys and the webhook, then run payment tests before enabling payments.
8. Import the first verified notifications, then connect Search Console and analytics.

Local development: `DATABASE_URL=pglite://./.data/dev` gives a zero-setup embedded Postgres (single process, so run `pnpm db:migrate`, `pnpm db:seed` and the dev server one at a time). Or point `DATABASE_URL` at the Render External Database URL. Production builds should run with the real `DATABASE_URL` or with it unset (demo data), not with PGlite.

Rollback: disable payments, unpublish affected posts, redeploy the previous Render deploy and restore the database from a Render backup when needed.
