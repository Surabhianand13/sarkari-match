# Launch checklist (soft launch: matcher, blog, waitlist; paid series later)

## 1. Code on GitHub
- Repo `Surabhianand13/sarkari-match`; deploy branch is `main`.

## 2. Render (hosting + database)
1. Render dashboard > New > Blueprint > pick the GitHub repo. It reads `render.yaml` and creates:
   - Web service `sarkarimatch-web` (Starter plan, Singapore, Node 24).
   - Postgres `sarkarimatch-db` (Basic 256 MB, Singapore). Upgrade the database before loading lakhs of questions.
2. When asked, fill the variables marked "sync: false":
   - `NEXT_PUBLIC_LEGAL_NAME`, `NEXT_PUBLIC_SUPPORT_PHONE`, `NEXT_PUBLIC_BUSINESS_ADDRESS`, `NEXT_PUBLIC_GRIEVANCE_OFFICER` (shown on the legal pages; leave blank only if not applicable).
   - `RESEND_API_KEY`, `EMAIL_FROM` (see step 4).
   - `NEXT_PUBLIC_WHATSAPP_NUMBER` (digits with country code), optional.
   - `TEST_CHECKOUT_URL` and `ANTHROPIC_API_KEY`: leave empty until the paid series and AI go live.
   - `AUTH_SECRET` and `ACCESS_GRANT_SECRET` are generated by Render. Copy `ACCESS_GRANT_SECRET` to your payment page later.
3. First deploy runs the database migrations automatically. Then, in the service's Shell tab:
   - `pnpm db:seed` (taxonomies and the three starter blog articles; sample notifications are skipped).
   - `pnpm db:create-admin` (your real admin email and password).
4. Check `https://<service>.onrender.com/api/health` shows `"database":"ok"`.
5. Settings > Custom Domains: add `sarkarimatch.com` and `www.sarkarimatch.com`.

## 3. Cloudflare (DNS, security, email)
1. Add `sarkarimatch.com` to Cloudflare. If the domain is registered elsewhere, change its nameservers to the two Cloudflare gives you.
2. DNS records: `CNAME @ -> <service>.onrender.com` and `CNAME www -> <service>.onrender.com` (Render shows the exact targets). Wait until Render verifies the domain and issues its certificate, then turn the proxy (orange cloud) on.
3. SSL/TLS: mode Full (strict); turn on Always Use HTTPS.
4. Redirect Rule: `www.sarkarimatch.com` to `https://sarkarimatch.com` (permanent).
5. Security: Bot Fight Mode on. **Turn off "Block AI bots / AI crawl control"**: you want Google, Bing, ChatGPT, Claude and Perplexity to read the site.
6. Caching: leave the defaults (static files only). Optional rule: bypass cache for `/api/*`, `/admin*`, `/dashboard*`.
7. Email Routing: create `support@sarkarimatch.com` and forward it to your own inbox (the site shows this address).
8. Resend DNS: add the SPF and DKIM records Resend gives you, so sign-in emails are delivered.

## 4. Email sending (Resend)
Create an account, add and verify `sarkarimatch.com`, create an API key, set `RESEND_API_KEY` and `EMAIL_FROM` (for example `Sarkari Match <hello@sarkarimatch.com>`) in Render.

## 5. Search and monitoring
- Google Search Console: add the domain property (verify with a DNS TXT record in Cloudflare) and submit `https://sarkarimatch.com/sitemap.xml`. Do the same in Bing Webmaster Tools.
- Uptime monitor (for example UptimeRobot, free) on `/api/health`.
- Check that Render Postgres backups are enabled for your plan, and restore-test once.

## 6. Content before people arrive (the matcher is the day-one product)
- Load 15 to 30 real, verified govt notifications (Admin > CSV import, or Admin > Posts). With none, `/jobs` is empty.
- Add the real offline reviews and expert details in `lib/trust.ts` if you want that section.
- Upload homepage banners (Admin > Homepage banners), 1800x600 desktop and 900x1200 mobile.
- Publish or edit blog articles (Admin > Blog).

## 7. When the paid series is ready (not day one)
1. Load questions for all four SSC CGL sections (Admin > Question factory or `pnpm questions:import`), review and publish them.
2. Admin > Exams and offers > SSC CGL: set the Guide on and price; Admin > Test series: create the series (price ₹999), add a free sample test, publish.
3. Build the payment page; set `TEST_CHECKOUT_URL` and give it `ACCESS_GRANT_SECRET`. Test in the provider's test mode end to end, including a payment below the quoted amount (must be refused).
4. Set `ANTHROPIC_API_KEY` (with a monthly spend limit in the Anthropic console) to turn on the AI Study Guide and the support assistant.
5. Set `NEXT_PUBLIC_HIDE_PLATFORM_STATS` to `false` only when the learner, question and test numbers shown are true, then redeploy.

## 8. Final checks
- Sign up, sign in, sign out, password reset path, eligibility matcher, blog, waitlist form.
- Open the site on a phone. Check `/robots.txt`, `/sitemap.xml`, `/llms.txt`.
- Read the Terms, Privacy and Refund pages once and confirm they match how you will operate (they are drafts, not legal advice).
